# Human–AI Collaboration SOC Dataset
### Supporting Dataset for the Paper  
“A Unified Framework for Human AI Collaboration in Security Operations Centers with Trusted Autonomy"

---

# 1. Overview

This repository contains the dataset used in the experimental evaluation of the Human–AI Collaboration framework for Security Operations Centers (SOCs). The dataset is derived from cyber range exercises conducted in the ACDC CyberAlly environment, where Red Team attack activities were simulated and Blue Team analysts investigated incidents using AI-assisted workflows.

The dataset captures the interaction between human analysts, AI assistants, and SOC infrastructure components, including incident tickets, AI-generated suggestions, and representative SIEM alerts.

The purpose of this dataset is to support transparency, reproducibility, and validation of the Human–AI collaboration framework presented in the paper.

# 3. Dataset Components

## 3.1 SOC Incident Tickets

The ticket datasets represent incident response cases handled by SOC analysts.

Typical fields include:

| Field | Description |
|---|---|
uuid | Unique ticket identifier |
locator | Ticket reference ID |
created | Ticket creation time |
modified | Last update time |
status | Incident handling stage |
severity | Incident severity level |
description | Incident description |
org | Organizational context |

These tickets represent analyst investigation workflows, including triage, analysis, containment, and recovery stages.

---

## 3.2 AI Assistant Suggestions

The suggestions datasets contain outputs generated by an AI assistant used during SOC investigations.

Typical fields include:

| Field | Description |
|---|---|
ticket_id | Linked SOC ticket |
analysis | AI-generated investigation summary |
recommendation | Suggested mitigation actions |
full_log | Associated log message |

These outputs demonstrate AI decision-support capabilities in SOC operations.

---

## 3.3 SIEM / Wazuh Alert Logs

To represent realistic SOC telemetry, the dataset includes representative SIEM alerts generated using a Wazuh-style structure.

Typical alert fields include:

| Field | Description |
|---|---|
timestamp | Time of alert generation |
ticket_uuid | Linked incident ticket |
agent | Host generating alert |
rule_id | Wazuh detection rule |
severity | Alert severity level |
src_ip | Source IP address |
dst_ip | Target system |
description | Alert description |

Example alert record:

timestamp,ticket_uuid,agent,rule_id,severity,src_ip,dst_ip,description
2023-05-01T10:12:00Z,E3-001,server01,5715,8,10.0.0.5,192.168.1.25,Credential anomaly detected

These alerts approximate typical SIEM outputs used in SOC environments.

---

# 4. Event Synchronization

The SIEM alerts are synchronized with the incident tickets to represent a realistic SOC timeline.

For each ticket:

1. Initial alert corresponds to the detection event triggering the ticket.
2. Follow-up alerts simulate correlated security observations.
3. Ticket updates reflect analyst investigation actions.

This synchronization enables analysis of:

- AI-assisted alert triage
- analyst decision workflows
- Human–AI collaboration dynamics

---

# 7. Limitations

To protect operational security and privacy:

- The dataset contains representative and anonymized data.
- Network identifiers and hostnames are generalized.
- Some SIEM alerts are synthetically generated to illustrate representative SOC telemetry.

However, the dataset preserves the structural characteristics of real SOC workflows.
